服务端已安装 · 如何连接

Tavern Card Studio Server 0.1.2（多账户版）。按 1 → 4 的顺序做完即可连通； 放在公网上再加做第 5 节。

1创建管理员账户必做第一步

0.1.2 起服务端按账户隔离卡片：没有账户，客户端登录不了 （自助注册默认关闭），只能退回用全局令牌做运维。所以装完先建一个账户。

从 0.1.1 或更早版本升级上来的，这一步没有替代做法。 老库是单用户模型 —— 只有一个全局令牌，卡片没有归属。迁移命令一次做三件事： 建首账户（自动成为管理员）、把历史卡片接管进它的默认仓库、动库之前先备份。

以管理员身份打开 PowerShell：

# 在安装目录里执行 —— tcs-server.cmd 会带对配置文件路径
cd "C:\Program Files\Tavern Card Studio Server"
.\tcs-server.cmd user migrate admin

提示「首账户密码」时输入（至少 8 个字符）。密码从标准输入读， 不接受命令行参数 —— 那样会留在 shell 历史与进程列表里。

跑完大致会看到：

将创建首账户「admin」（管理员）并接管 12 张历史卡片。
原库会先自动备份（VACUUM INTO，含最新事务）。
已创建首账户「admin」（管理员），接管 12 张历史卡片；
仓库：新建 1 个默认仓库、12 张卡片入库；
原库已备份到 C:\ProgramData\TavernCardStudio\store\state.db.pre-accounts-….bak
  • 全新安装也用同一条命令，只是「接管 0 张卡片」。
  • 重复执行是安全的：已有账户时它只补默认仓库、把没归仓库的卡片入库。
  • 不需要重启服务：账户是每次请求现查库的。
  • 要加普通成员：.\tcs-server.cmd user add bob --role user
  • 确认结果：.\tcs-server.cmd user list
必须用安装目录里的 tcs-server.cmd。 它替你指定了服务正在用的那份配置（C:\ProgramData\TavernCardStudio\config.json）。 如果绕过它直接跑 node.exe app\server\dist\index.js user migrate， 程序会按当前目录另算一个数据目录，等于在旁边新建一个空库 —— 症状是「账户明明建好了，服务却说不存在」。

2两个地址，分别用于不同用途

用途地址说明
管理面板 http://127.0.0.1:8731/ 浏览器打开：看卡片、改配置、取令牌、查日志
API http://127.0.0.1:8730 客户端填这个，不要填面板地址

0.1.2 起两者彻底解耦：API 监听地址与面板监听地址是两个独立配置项， 改一个不会连带改另一个。把 API 改成 0.0.0.0 给局域网用时， 面板仍只监听本机 —— 这是刻意设计：面板本身不带登录，不该出现在局域网上。

3三种令牌，先弄清再用

0.1.2 起服务端有三类凭证，权限范围完全不同：

凭证 从哪拿 能看到什么 适用
账户令牌
推荐		 客户端「登录」：填用户名 + 密码自动换取，有效期 2 小时并自动续期 该账户的全部仓库 客户端日常使用。有账户就该用它
仓库令牌
tcr_…推荐		 客户端「仓库与令牌」里签发（需先登录账户），可设有效期 只限某一个仓库，范围分 read / write / rollback 脚本、CI、共享给他人只读。原文只显示一次
全局令牌
legacy		 面板「API 与令牌」页；或在安装目录运行
tcs-server.cmd token show
也写在配置文件 auth.token		 只有尚未归属账户的卡片（0.1.2 起降权） 仅运维：接手历史数据、排查。不要用于日常
迁移完成后，全局令牌看不到任何卡片。 因为卡片都已归属到账户，而全局令牌只保留「未归属卡片」的可见范围。 它的设计用途是运维凭据，不是给人日常浏览的。 需要看卡片，请在客户端里登录账户（账户令牌）。

4在客户端里连上

  1. 打开 Tavern Card Studio 客户端，进入「设置」。
  2. 「服务端地址」填 http://127.0.0.1:8730（是 8730，不是面板的 8731）。
  3. 点「测试连接」，看到「已连接（服务端 0.1.2），token 有效」说明网络与令牌都通了。
  4. 再点「登录」，用第 1 节建的账户登录 —— 登录后才会以账户身份看自己的卡片与仓库。

「连接本机服务端」按钮

客户端与服务端装在同一台机器上时，可以直接点这个按钮： 它会探测本机的 8730 / 8731，自动把「服务端地址」和「访问令牌」填好， 省掉手抄。它填进去的是全局令牌，所以不代替登录—— 要看自己的卡片，仍然要点「登录」。

如果它报「API 端口对得上、面板对得上，但令牌取不到」，多半是反代没登记信任 （见第 5 节 trustProxy）；如果它报「端口变了」， 回面板「参数配置」看实际监听地址。

5公网 / 云部署检查清单

只在本机或内网用，可以跳过这一节。要放到公网上，逐条确认：

检查项怎么做
① 选对 tls.mode off 仅本机/可信内网；selfsigned 自签证书（客户端首次要核对指纹）； custom 用你自己的证书。放在反向代理后面时，业务侧可以是 off， TLS 由代理终止。证书默认在 C:\ProgramData\TavernCardStudio\tls\。
② 显式配置 trustProxy 默认是空数组 = 不信任任何代理头。放在反向代理后面就必须把代理地址填进去 （同机通常是 127.0.0.1），否则服务端只会看到代理的 IP： 取令牌接口一律拒绝、登录失败限速会把所有人算成同一个来源。 配置后打开面板「总览」页，「可信代理」那一行应当显示已生效的代理数 —— 一直是 0 说明地址写错了。
③ 防火墙只放 httpsPort 用 HTTPS 时只对外开 httpsPort（默认 8443），把 port（8730） 与面板端口（8731）挡在防火墙后面。注意：开启 TLS 后明文端口仍会同时服务， 没有独立关闭开关，所以这一条只能靠防火墙做到。

更完整的部署形态（Caddy / nginx 反代、证书选型、首次建管理员流程）见项目文档的云部署手册。

6常见问题

现象处置
面板 127.0.0.1:8731 打不开 服务可能没启动。打开「服务」(services.msc)，看 Tavern Card Studio Server 的状态，不是「正在运行」就右键启动。
服务启动失败（SCM 报 1067 / 一直「正在启动」） 看 C:\ProgramData\TavernCardStudio\logs\tcs-service-host.err.log。 若出现 Cannot find package，说明安装包缺运行时依赖 —— 用 0.1.2 的修复版重装；也可在安装目录跑 .\tcs-server.cmd selfcheck 离线核对依赖。
登录提示账户不存在 / 密码错 先在安装目录跑 .\tcs-server.cmd user list 确认账户在服务用的那个库里。 如果 list 里也没有，多半是第 1 节那条警告：命令没在安装目录里跑。
登录后看不到以前上传的卡片 历史卡片还没归属。跑 .\tcs-server.cmd user migrate admin （已有账户时它会把没归属的卡片接管进来），或对指定账户跑 user adopt <用户名>。
客户端提示「令牌无效」 用的是全局令牌，而它已被降权 / 轮换过。改用「登录」。 若在面板点过「轮换令牌」，旧全局令牌会立即失效。
改了端口后连不上 回面板「参数配置」确认实际端口，客户端地址跟着改。改完需要重启服务。

数据目录：C:\ProgramData\TavernCardStudio\　·　 卸载时该目录会保留（里面有卡片与版本历史）
