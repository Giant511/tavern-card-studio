## 1. 一条原则（不可让步）

**语音不是开箱即用功能，是"自带密钥"功能。**

| 情形 | 行为 |
|---|---|
| 未配置 | 麦克风按钮**置灰**，点击弹**配置引导**（不是什么都不发生） |
| 已配置但不可用 | **明确报错**，不允许静默置灰 |
| 已配置且可用 | 按住说话 → 转写 → 文本进聊天链路 |

> ⚠️ 「静默置灰」是需求点名禁止的两种做法之一。
> 它的问题不是"不美观"，而是**用户无法区分"我没配"和"配了但坏了"** ——
> 前者他知道去配，后者他只会以为这功能是废的。

## 2. 隐私承诺（红线）

```text
用户密钥 → 只存客户端
音频     → 客户端直接发到用户自己配置的第三方
TCS 服务端 → 零接触：不经手、不存储音频，也不存储转写文本
```

**为什么这条要写进仓库而不是留在补丁里**：它是对用户的承诺。
将来任何人想"顺手"加一个服务端中转（比如为了统一计费、为了缓存、为了脱敏），
本文是那个"不行"的依据。

「无注入、无模拟点击」（§二 技术架构）是同一族的约束：
ASR 通道的输出是**一段文本**，经 `st-adapter` 进聊天，
不是去操作 ST 的界面。

## 3. 配置形态

三个字段：`base_url` + `api_key` + `model`。

### 3.1 三条协议路线

| 路线 | 协议 | 可接 | 定位 |
|---|---|---|---|
| **A（默认）** | OpenAI 兼容转写 `POST /audio/transcriptions` | OpenAI Whisper / Groq / 阿里百炼 Paraformer / 本地 `whisper.cpp` 自建服务 | 一套代码通吃 |
| **B（高级）** | 音频走 **chat 协议**上传 | Qwen-Audio / Gemini 类多模态 | 抗噪与中文口语更强 |
| **C（自建）** | **Gradio** `upload → call → poll`（决策 #338） | Fun-ASR / Whisper-WebUI / SenseVoice 等开源项目默认起的 Gradio 页面 | 用户在局域网里已经跑起来了，只缺一个能填地址的客户端 |

三类服务形态至此齐备：**OpenAI 兼容**（有标准接口）、**音频理解模型**（要按厂商
形状分叉）、**Gradio 私有协议**（没有标准接口，请求体是位置参数数组）。

需求原文的理由（决策 #266）：**只做 A 会漏掉一类明显更好的效果；只做 B 门槛太高**
（多数厂商不支持）。

> **设计时必须回答（现在没答案）**：
> - 路线 B 的请求体形状各厂商不同（`input_audio` vs `inline_data` vs `audio_url`），
>   要不要像 `st-adapter` 那样再分一层解包？
> - 两条路线共用一个 `model` 字段够不够？B 路线可能还需要指定"音频格式"参数。

#### 3.2.4 中转站支持（设计定稿 2026-10-29）

**① 独立成条目，不是"改某个厂商的 base_url"**

因为「中转站 base_url + 直连厂商的 model 名」是一个**必然失败**的组合：
中转站的模型 ID 是它自己起的名字（`whisper-1` / `-xl` / 自定义别名），
与直连厂商不是一套。混在一条里，用户会填出这种组合然后拿到 404。

**② 「获取模型列表」**

```text
GET {base_url}/models（带 key）
  成功 → 模型名下拉框
  失败（401/403/404/405/任意非 2xx） → 静默降级，保持手填，不报错打扰
```

实现：`shared/src/asr/models.ts`（`buildModelsUrl` / `parseModelsResponse` / `interpretModelsResponse`）。

> **为什么 401 在这里也静默**（与"不许静默置灰"不冲突）：
> `GET /models` 需要**额外的权限范围**，很多站的 key 允许转写但不允许列模型；
> 此时 401 完全不说明转写不可用。**真正的判据是那段 3 秒测试音频**。
> 若这里因 401 弹"密钥无效"，用户会去换一个本来好用的 key。
>
> 区别在于**主流程是否还能继续**：麦克风静默置灰 ⇒ 用户不知道功能存在（不可接受）；
> 列模型失败 ⇒ 手填一直可用（可接受）。

`buildModelsUrl` 有三条实测会踩的边界（都有单测）：

| 输入 | 输出 | 为什么 |
|---|---|---|
| `.../v1/` | `.../v1/models` | 不去尾斜杠会拼出 `//models`，部分网关 404 |
| `.../v1/audio/transcriptions` | `.../v1/models` | 中转站文档常给**全路径**，用户会整段复制 |
| `https://relay.com` | `https://relay.com/models` | **不擅自补 `/v1`** —— 有的站是 `/api/v1`、`/openai/v1`，猜错比不补更糟 |

**③ 测试音频的错误分流**

| HTTP | 提示 | 用户该改什么 |
|---|---|---|
| 401 / 403 | 密钥无效或余额不足。 | 换 key / 充值 —— **换厂商没用** |
| 404 / 405 | 该中转站不支持语音转写接口（/audio/transcriptions），请更换中转站或使用直连厂商。 | 换中转站或改直连 —— **换 key 没用** |
| 超时 / 网络失败 | 连接超时 / 网络请求失败。 | 换网络 —— **改配置没用** |
| 429 | 请求太频繁或额度已用尽，请稍后重试。 | 等一会儿 |
| 转写为空文本 | 测试音频没有转出任何文字。请确认服务正常，或检查模型名是否填对。 | 检查模型名 |

> 三类处置**互相排斥**，混成一句"配置不可用"，用户必然去改那个没坏的东西。
> 实现见 `shared/src/asr/errors.ts`，测试见 `test/asr-errors.test.mjs`（19 项）。
>
> ⚠️ **一个已注意到但没擅自改文案的边界**：定稿的 404 文案是面向**中转站**写的
> （因为这是最常见情形）。而直连厂商如果 base_url 少了 `/v1` 也会 404，
> 此时"更换中转站"是错的指引。定稿已拍板，故原样使用 ——
> 要补直连场景的提示需要再定一次文案。

**④ 隐私文案补充**

```text
使用中转站时，音频会经过第三方服务器。
```

> 与 §2「服务端零接触音频」并不矛盾，但**必须补上**：直连时音频只到厂商，
> 走中转时多经过一层第三方。不写这一句，"隐私优先"就成了空头承诺。

**⑤ 聊天后端（F5）的中转站**

ST 的 `custom` 源 + `reverse_proxy` **本来**就是中转站接法，所以只加一句说明：

```text
支持 OpenAI 兼容中转站：后端选「自定义」，在反代地址里填中转站地址即可。
```

**不额外开发** —— 定稿明确要求。写进常量 `CHAT_RELAY_NOTE`，
是为了让它和 ASR 侧的中转站说明成对出现：将来有人想在聊天侧"也做一个中转站配置页"时，
能看到这里已经有答案了。

#### 3.2.5 为什么是"一张表"而不是 if/else

决策 #267 的原话：「模板表随版本维护，新厂商加入只改表不改代码」。

写成 `if (vendor === 'groq') { ... }` 的代价不是"代码难看"，而是每加一个厂商都要
改逻辑、走一次发版、过一遍回归。而这张表里没有逻辑，只有「厂商 → 默认值」的映射。

**厂商改名/停服的降级**（原"设计时必须回答"的问题，现在有答案）：
`findAsrPreset(id)` 对未知 id 返回 `null` 而**不抛错** —— 配置里可能存着旧版本的 id
（用户升级前选的厂商），抛错会让整个配置页打不开。UI 据此显示"原配置已失效，请重新选择"。

#### 3.2.5 第三条路线的预设：「本地 Fun-ASR（Gradio）」（决策 #338）

| 字段 | 值 | 为什么 |
|---|---|---|
| `id` | `funasr-local` | 稳定标识，不许改 |
| `protocol` | `gradio` | 第三条路线 |
| `baseUrl` | **空（手填）** | 服务在用户自己的机器上，地址只有他知道。提示语：`填部署机器的局域网地址，如 http://192.168.1.x:7860` |
| `model` | `fun-asr-nano` | 该应用的合法取值之一 |
| `modelPath` | `./models/Fun-ASR-Nano` | **另一个字段**，见下 |
| `requiresKey` | `false` | 自建服务没有鉴权 |

**为什么 `model` 与 `modelPath` 必须分开**：前者是"选哪个模型"（`fun-asr-nano` /
`sensevoice`），后者是"权重放在哪"。合并成一个输入框，用户改其中一个就要改另一个，
且填错时分不清是哪个错。

#### 3.2.6 Gradio 协议的实现要点

实现：`shared/src/asr/gradio.ts`（纯逻辑）+ `client/src/chat/asr-client.ts`（发请求）。
测试：`test/asr-gradio.test.mjs`（29 项，含一个最小 HTTP 桩跑全链路）。

三步调用（真机对齐 2026-11-01，Gradio 6.2.0）：

```text
① POST {prefix}/upload                         multipart files=<音频>
   → ["C://...//gradio//<hash>//voice.wav"]        （服务端路径）
② POST {prefix}/call/{endpoint}                {"data": [参数...]}
   → {"event_id": "dc543b65..."}
③ GET  {prefix}/call/{endpoint}/{event_id}     （SSE 流）
   → event: complete
     data: [指标, "转写文本", 文件信息]
```

**转写文本固定取三元组的 `[1]`。** 不是"找第一个字符串"：指标那一项在部分版本里
也是字符串（纯文本日志），找第一个字符串会把日志当成用户说的话发出去。

**参数数组靠 `GET {prefix}/info` 探测，不写死位置。** 第②步的 `data` 是按位置排的，
插错位置不会报"位置错"，而是让服务端拿着字符串当音频 —— 表现为莫名的 500。
探测来的参数表按"组件类型 + 服务端默认值"填：

| 参数 | 填什么 |
|---|---|
| 组件是 `Audio` | 上传后的文件对象 |
| 有默认值 | 服务端默认值（那是它自己的合法取值） |
| 认得出是模型名/模型路径 | 用**用户配置**覆盖默认值 |
| 没有默认值 | `null`（Gradio 的空值；空串会被当成"给了个空链接"） |

认不出身份时落到服务端默认值 —— 失败模式是"用户改了没生效"，
而按位置硬覆盖的失败模式是"整套错位、500"。前者可解释，后者不可查。

**流被掐断时要保留已收到的内容。** 真机踩过：推理中途 worker 死掉，SSE 流被直接关闭，
`response.text()` 抛 `TypeError: terminated`，**已收到的错误全丢**，
于是只能报"网络失败"——而服务端其实已经把原因发过来了。现在逐块读，读失败保留部分。

### 3.3 兼容性校验（判据级）

```text
保存配置时 → 发一条 3 秒测试音频 → 实跑转写 → 成功才允许启用
```

| 项 | 要求 |
|---|---|
| 测试音频 | 3 秒，**内置在应用里**（不能让用户先录一段才能保存） |
| 判据 | 转写**返回非空文本**才允许启用 |
| 失败 | 明确报错。要能区分"key 错" / "base_url 错" / "model 名错" / "网络不通" |

> **设计时必须回答**：3 秒音频的内容（人声说什么？）、放哪个格式（wav/mp3/webm）、
> 以及**校验失败时是"不许保存"还是"保存但标记不可用"**。
> 后者更宽容（用户可能只是暂时断网），但必须让状态可见。

### 3.4 厂商能力边界（决策 #268 —— **口径已修正**，2026-10-29）

**DeepSeek / Kimi 等纯文本厂商没有语音识别能力。**

## ⚠️ 与初版口径的差别（重要）

| | 初版（补丁 §F4 原文） | **定稿（2026-10-29）** |
|---|---|---|
| 做法 | 配置页给出提示 | **选项里不出现** |
| 提示位置 | 配置页内 | **只在使用说明里** |

**为什么后者更好**：「列出来再报错」本身就是一次挫败 ——
用户要先选、填 key、跑测试、失败，才知道这条路不通。
而说明里的一句话，是在他**动手之前**就把它排除掉。

实现常量：`TEXT_ONLY_VENDORS_NOTE`。

```text
DeepSeek、Kimi 等纯文本模型没有语音识别能力，不能用于语音配置；
它们的正确位置是聊天后端。
```

> 文案里必须给出**正确位置**（聊天后端）—— 只说"不能用"会让用户以为这个 key 白买了。
>
> 原文点出的失败场景仍然成立：用户把 DeepSeek 的 key 填进语音配置 → 得到"配置不可用" →
> 不知道为什么 —— **而它明明在聊天那边工作正常**。
>
> 这条提示要进 `verify-ui-copy.mjs` 的检查范围（决策 #268 明写）：它属于"配置页文案"。
> 单测里有一条专门断言 `findAsrPreset('deepseek') === null`，防有人"顺手"把它加回下拉。

## 4. 与 F5（聊天 LLM 配置）的边界

| | 语音 ASR（F4） | 聊天 LLM（F5） |
|---|---|---|
| 配置在哪 | 我们自己的配置页 | 聊天面板「API 连接」页 → **走 ST 的设置接口存储** |
| 存哪 | 客户端本地 | ST 的 `settings.json` / `secrets` |

> 这两块**不许共用一套配置**。共用的后果是"改语音厂商把聊天模型也改了"，
> 而用户完全不会预期这个。

## 6. 语音交互（终版，2026-10-30 定稿）

> **本文是唯一真相。** 此前分散在各处的增补（滑动选模式、实时波形、确认流、
> 配置独立性）已全部并入本节，旧说法一律作废。决策 #303–#309。

### 6.1 模式选择：滑动选（默认「说话」位，零额外点击）

**交互**：

- 按住麦克风 → 上方浮起三个 chips：`[🗣 说话] [💭 内心/动作] [💬 消息]`，
  默认焦点在「说话」；
- 手指滑向目标 chip（高亮 + 波形变色）→ 松手按该模式发送；
- **不滑动直接松手 = 说话**（最常用路径零成本）；
- 模式**按会话记忆**（`CardSession.voiceMode`），新会话回默认「说话」；
- chips **常驻显示当前模式**（未按住时也是状态指示）。

**拼接规则**（`shared/src/voice/wrap.ts` 的 `wrapVoiceText`，纯函数可单测）：

| 模式 | 包裹 | 码位 |
|---|---|---|
| `speak` | `“文本”` | U+201C / U+201D（**中文弯引号，不是 ASCII `"`**） |
| `inner` | `(文本)` | `(` / `)`（全角 `（）` 也算已包裹） |
| `message` | `「文本」` | U+300C / U+300D |

- 已含**同类**包裹符不二次包裹（防 ASR 转出引号）。判据是"同时以开符开头、
  以闭符结尾"，**不是"包含"** —— 用"包含"会让 `他说“你好”` 失去语音标记；
- 空文本 / 纯空白**不发送**（`reason: 'blank'`）。

**为什么是确定性拼接，不用 LLM 分类**（决策 #303）：

1. 可预测 —— 用户选什么得到什么，不存在"模型理解错了"这种无法申诉的失败；
2. 零延迟 —— 本地字符串操作；
3. 可测 —— 三模式的期望值能写成字面断言。LLM 分类只能测"大概对"。

**为什么滑动优于另两个方案**（决策 #303）：

- 优于「预先点选」：省一次点击，且**松手前有视觉确认**（滑到哪儿高亮就在哪儿）；
- 优于「发前预览」：预览让每条语音都多一步；需要的人可以开确认流（§6.3），
  但**不默认**。

**为什么判据是"落在 chip 矩形里"而不是"滑动方向"**：

方向判定（上滑=内心、左滑=消息）需要用户记三个方向的语义，
且手抖会在 45° 边界附近反复切换高亮（看起来像卡了）；
落点判定天然带"没打中就回默认"的安全性质。命中区默认外扩 12px 补偿拇指误差。

### 6.2 按住实时波形（v1 范围，决策 #305）

按住录音期间，浮层中央显示实时波形：

- Android 录音振幅驱动（`MediaRecorder.getMaxAmplitude()`，0..32767）；
- **渐变着色**用 `--nb-grad-primary`（夜航设计册，与语音按钮同族）；
- **120ms 刷新**（`WAVEFORM_REFRESH_MS`）；
- 松手即停并**定格一帧**后进入发送/确认流。

两条让波形"看起来对"的细节（都在 `shared/src/voice/waveform.ts`）：

1. **对数映射**，不是线性。人说话大部分落在 2000–8000 这个窄低段，
   线性归一化会让柱高长期贴底，用户以为没在录。
   实测：10% 量程（3277）→ `0.279`。
2. **静音画一条细线**（`MIN_BAR_LEVEL = 0.06`），不是 0 —— 否则波形断开、像坏了。
   同时做**峰值保持**（每帧最多降到上一帧 40%），避免逐帧归零造成的抖动。

### 6.3 消息呈现与确认流

**消息呈现**：

- 语音发送的用户消息 = 正常气泡 + **小麦克风徽标** + 已包裹正文
  （「气泡下显示实际发送的文字」= 徽标 + 正文常态显示）；
- 语音标记**随消息走**：发送时写 `extra.tcs.voice = true`。
  契约 §5.3 要求 `extra` 逐字段保留 ⇒ 切设备 / 回桌面端徽标不丢。
  纯函数 `setVoiceFlag` / `isVoiceMsg` 可单测（决策 #306）；
- **包裹后文本即消息本体**，ST 侧零特殊处理。

**确认流**（设置项「语音发送前需确认」，**默认关闭**，决策 #307/#308）：

| 状态 | 流程 |
|---|---|
| 关（默认） | 按住 → 转写 → 自动包裹 → **直发** → 气泡出现，零中断 |
| 开 | 转写完成 → 输入区上方待确认条 `[波形缩略] [已包裹文本（可编辑）] [发送] [取消]` |

- 发送前**不进气泡**；
- **编辑对象是已包裹文本**（所见即所发）；
- **取消 = 本次语音直接作废**：不落消息、不留输入框
  （用户已拍板；状态机 `cancelDraft` 返回 `idle` 且 `draft: null`）；
- 设置位置：「我的 → 语音输入 → 发送前确认」，C5 持久化，**独立于 ASR 三字段**。

**转写完成态 = 可编辑**（语音填词而非盲发）：两种模式下转写文本都先经输入链路；
关闭确认时自动发送，开启时停留待确认条；输入框内所见即所发。

### 6.4 配置独立性（重申，防接线合并，决策 #309）

ASR（`asrBaseUrl` / `asrApiKey` / `asrModel` / `asrPresetId`）与聊天后端
（聊天面板「API 连接」页，走 **ST 设置接口**存储）是**两套独立配置**：
互不可见、互不覆盖；改任一侧不动另一侧。

**落到代码上**是 `shared/src/config-scopes.ts` 的 `applyScopedPatch`：

- 声明两套键集合（`ASR_CONFIG_KEYS` / `VOICE_PREF_KEYS`）；
- 跨作用域写入**当场抛 `ConfigScopeError`**，不是静默忽略；
- `overlappingConfigKeys()` 断言两者不重名。

为什么值得这么防：它们的失效形态是"改 ASR 厂商之后聊天突然不能用了" ——
两件事在用户心里毫无关联，查起来极难。

三条断言口径上值得留意的取舍：

1. **字面值按码位断言**。若按字形（`assert.equal(text, '“你好”')`），
   源码里写成 ASCII 直引号的**错误实现也能通过**；
2. **静音回落要喂足够多帧**。峰值保持是有意的（防抖动），

3. **波形曲线不断言精确值**（0.2788），只断言性质（> 0.25）——
   写死精确值会让日后调参变成改测试。
